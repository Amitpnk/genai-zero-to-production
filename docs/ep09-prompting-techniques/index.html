How to choose few-shot examples

Use real inputs

Messages like the ones you'll actually get.

Keep them out of the test set

Otherwise your score is fake.

Cover the hard cases

Messages on the line between two labels.

Watch for copying

Answers matching your examples' labels = copying.

Order can matter

The last example often pulls hardest. Shuffle.

Test several sets

Keep the best per-label scores.

Always check accuracy per label, not just overall

Reasoning (“thinking”) models

What changes

They think before answering, on their own

A hidden chain-of-thought. “Think step by step” in the prompt adds less.

What stays the same

You still pay for the thinking

Control it with a setting (thinking budget or effort). More thinking = better on hard tasks, but more tokens and slower.

Interview question · FDE

“When would you use few-shot prompting, chain-of-thought, or fine-tuning?”

A strong answer

Start zero-shot with a test set and automatic checks. If format or labels are wrong, add few-shot examples from real data, test several sets, and check accuracy per label for copying. If the task has steps, add chain-of-thought or a reasoning model, only where it pays off, because it costs far more output tokens. Fine-tuning comes last: prompting has hit its limit, the task is narrow and high-volume, and I have hundreds of labelled examples. Missing knowledge needs retrieval, not fine-tuning.
