Your app keeps the history and resends all of it, every turn. That's also why long chats cost more (Ep 4).

Real output · a chatbot's whole “memory” is a Python list

A chat loop in plain Python

history = []

while True:
    question = input("You: ")
    history.append({"role": "user", "content": question})

    reply = chat(history, system=SYSTEM)          # send EVERYTHING
    print("AI:", reply.text)

    history.append({"role": "assistant", "content": reply.text})

In production: trim or summarise old turns, and keep history server-side per user.

Interview question · FDE

“Walk me through an LLM API call, and what you'd add to make it production-ready.”

A strong answer

The app sends the model ID from config, a system prompt, the conversation as messages and settings like max tokens, authenticated with a key from a secret store. It gets back text, a finish reason and usage. The API is stateless, so I keep chat history server-side and trim it. For production: timeouts, retries with backoff for 429s and 5xx, streaming, a finish-reason check, logging of tokens, latency and cost, and one swappable wrapper around the provider.
