The six parts of a prompt

Role

Who is the model?

Fixes tone and point of view

Context

What does it need to know?

Fixes made-up facts

Task

What exactly should it do?

Fixes answering the wrong question

Constraints

Rules and limits

Fixes too long, off-policy

Examples

What does good look like?

Fixes inconsistent style

Output format

Shape of the answer

Fixes output code can't parse

Not every prompt needs all six, but a failure usually points to a missing or unclear part

Make it a reusable template

@dataclass
class Prompt:
    role: str
    context: str            # "...Customer message: <message>{message}</message>"
    task: str
    constraints: str
    examples: str
    output_format: str

    def render(self, **values):
        parts = [self.role, self.context, self.task,
                 self.constraints, self.examples, self.output_format]
        return "\n\n".join(p.format(**values) for p in parts if p)

Each part is a separate field, so you can change and test one at a time.

Proper evals come in Module 9

Interview question · FDE

“A customer's prompt works 80% of the time. How do you debug it?”

A strong answer

Make it measurable: collect the failures, build a test set of real examples, and write automatic checks for what “working” means, including the decision, not just the format. Run each version several times. Map each failure to a prompt part: missing context, unclear task, unstated constraint, a biasing example, an ambiguous format. Change one part at a time and keep what raises the pass rate. If it still fails, consider structured outputs, another model, or retrieval.
